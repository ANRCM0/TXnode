# Actual configuration and user revocation in both Node kernels

The [contract](../../contracts/node-protocol/kernel-application-boundary-v1.md) retains both sing-box and Xray. A requested configuration is confirmed only after the selected kernel completes its actual operation.

Sing-box compares the complete generated construction independently of the user list. Outbound topology, routing, DNS, protocol, listeners and TLS changes require stop plus full reconstruction. Same-construction user changes keep the runtime, authentication replay owner and meters. Raw route, detour, selector and DNS outbound references are validated before mutation. Unknown targets fail with a fixed diagnostic instead of becoming falsely applied. Reverting a failed request to an earlier successful config remains retryable even though the kernel is stopped.

Xray validates the whole desired memory-user set before manager operations. Partial addition returns an error and does not advance local users, hashes or limits. Subset removal and UUID replacement explicitly require stop/reconstruction, because individual established-session close is not available. The capability stays false. Stop cancels and closes the old instance and retains final cumulative stats; restart releases the old port before binding the new instance. This can interrupt unaffected streams, which then authenticate under current desired users. A failed replacement cannot leave an uncertain old instance serving.

The [verification report](kernel-application-verification.json) records full race, vet and release builds plus actual VLESS/VMess Service streams. Tests observe real SOCKS outbound A-to-B traffic, invalid target refusal and recovery, protocol/port replacement, Xray established-stream closure, revoked UUID refusal, current-user recovery and unreported counter preservation. HTTP fixtures and main-loop events do not replace true Core/Workerman Machine acceptance, which is the next basic control slice.
