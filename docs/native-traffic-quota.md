# Native traffic and quota closure

The [traffic contract](../../contracts/node-protocol/native-traffic-quota-v1.md) and [observed-period contract](../../contracts/node-protocol/native-traffic-period-v1.md) reuse existing Node meters, durable report IDs, Core traffic hooks, the atomic TrafficBatchJob and reset service. No isolated Usage-v2 or global migration authority is activated.

Core persists a unique native receipt before HTTP202. First raw traffic identity, normalized hook output, rate/day and period segments remain immutable. A missing Redis wakeup cannot remove the receipt; `traffic:native-recover --limit=100` restores original settlement input. Conflicting replay returns409, unavailable durable storage503. Actual ledger existence is required before marking settled, and a crash after settlement but before that marker replays without double charge.

Core desired users carry signed reset epochs. Node binds the observed epoch before admission and closes/samples the old producer before a period transition. Sing-box has an explicit fresh cumulative generation; Xray retains its cumulative meter. Signed reports preserve per-user/epoch segments through failed delivery, disk spool, stopping and restart. Current epoch charges current quota; older epochs retain period history and statistics without consuming the new cycle. Historical unattributed reports preserve their explicit arrival semantics.

Ordinary batches bound traffic JSON to512KiB and10,000segments. Stop captures all remaining chunks into one immutable terminal bundle; each has its own original ID, pending comes first, partial ACK leaves file bytes unchanged, and complete ACK removes it. File/capacity/persistence errors remain visible and do not certify saved tail. Native pending-only restart also replays before opening listeners. Signed shutdown and unsubmitted-spool failures preserve original period labels.

Quota reconciliation reads settled receipts and retained Redis hints, selects integer/string groups, and publishes current users. Workerman rereads current authority when sending. Failed publication or zero subscribers leaves the candidate retryable. `traffic:health` distinguishes durable pending receipts, failed receipts, pending quota notifications, failed jobs and queue size; it does not assert global drain. Redis retry_after exceeds the traffic job timeout.

The [verification report](native-traffic-quota-verification.json) records actual trusted TLS, Core/Workerman, Redis worker and VLESS/VMess bytes. Tests kill and restart an actual Node process with the same pending file, kill PHP workers before/after SQL commit, lose ACKs and queue messages, freeze the original rate, exhaust quota and reset through registered admin endpoints. Delayed queues and network-held reports remain in the observed old epoch, while new bytes charge the current epoch. Independent SQL sessions verify both reset lock orders and older repeatable-read statistics; overflow rolls back the whole settlement.

End-to-end protocol evidence is VLESS/VMess on sing-box; local real TCP tests cover both kernels and UDP tests cover the generic packet meter boundary. Other protocol variants, unseen offline time boundaries, production PKI/key recovery, finite leases, HA and global authority cutover remain separate work.
