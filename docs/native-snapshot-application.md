# Native snapshots and confirmed kernel application

The [current contract](../../contracts/node-protocol/native-snapshot-application-v1.md) preserves a complete native snapshot beside its transport ETag. A valid304 can redeliver complete cached content; it never invents an empty user set. Configuration received before a later user request failure remains available on the next poll. Missing-cache304 retries once without a conditional header, then reports failure. Cached bodies are cloned and bound to one configured identity.

Service keeps desired config/users separate from successfully applied hashes. Start, Reload and user mutation advance confirmed state only after success. Failed application remains pending and the same push or complete snapshot can retry. A partially failed user mutation stops an uncertain kernel instead of continuing to serve revoked users or forgetting the authoritative desired state. Empty desired users close the listener. Invalid configuration and one-shot certificate renewal remain visible until the relevant application succeeds.

Every asynchronous poll captures the current local event generation. A newer accepted WS config/users/delta invalidates older ordinary poll results and schedules a fresh read. Completed authority denials remain terminal. Reconnect/drop invalidates transport caches. This is local ordering evidence, not a globally monotonic Core revision or an atomic shared config/users transaction.

Real VLESS and VMess connection tests exposed a concurrent authentication-map update race. The pinned local protocol dependency publishes immutable coherent authentication indexes, retaining the same VMess replay filter and wire/cryptographic algorithms. The inbound carries the authenticated identity from that exact generation instead of resolving an old array index against a new list. Legacy key refresh and shutdown are synchronized without holding a lock over client network I/O. Concurrent live clients and cross-update AEAD replay tests remain in the suite.

Full race also exposed a startup metering window: trackers were registered after listeners opened. Both native and bounded trackers are now completely initialized and registered before inbound Start, preventing early authenticated traffic from bypassing metering. A failed replacement does not overwrite the existing tracker.

The [verification report](native-snapshot-application-verification.json) records frozen source/dependency hashes, failed reproductions and final gates. Actual HTTP fixtures and sing-box proxy streams prove config200/users503 followed by304 recovery, occupied-port failure then same-snapshot recovery, and stale poll rejection after a newer user removal. Ordinary real Core TLS/admin-disable tests additionally prove listener/stream closure, exact43/79 terminal bytes and denied restart under each protocol.

Tests using a scripted WS event queue prove the Service boundary; they do not certify a real Workerman deployment. Machine-wide live integration, finite offline authorization, true custom-outbound reload, Xray strong revocation and durable Core applied-revision confirmation remain separate P0 work. No whole-plan or production migration completion is claimed.
